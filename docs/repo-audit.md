## 源码范围

开发位置为当前 comath 目录中的独立 co-mathematician checkout，分支 codex/local-web-workbench。原本机 Co-Mathematician checkout 含未提交的研究记录，未复制其改动，也未修改原 checkout。

开始时 GitHub 连接暂时失败，先从本机仓库的已提交代码建立开发副本。随后 fetch 成功，目标 main 仍为 e0ee848；参考仓库远端 HEAD 为 d609822，与两份原附件描述的源码一致。

原 Python Core 具有项目创建、列出、读取、恢复、归档及研究文件工作流。它不运行内置模型，也没有网页服务。本轮新增 web_service/bridge 以及 Node 和 React 应用，原 CLI 命令、研究工作流及文件结构保持兼容。

参考阅读了教材项目的 package.json、server/pi-agent.mjs、Vite 配置和 SDK 类型定义。新应用独立实现，未复制课程业务或修改参考仓库。未新增原方案中的哈希绑定、审批凭证、冻结副本、JSON Schema 或测试目录。

## 实际运行

- Python 3.13.5、Node.js 26.8.1、macOS。
- 原 CLI `python -m harness.co_math.cli --help` 正常；CLI `status --project` 读取到了网页创建的研究问题。
- `npm run check` 通过；`npm run build` 通过。构建仍提示单个前端 bundle 较大，主要包含数学渲染；这是性能优化余项。
- 依赖安装采用锁定直接依赖版本、无新增锁文件的方式。更新 Vite 到 6.4.3 后，安装过程报告 0 个已知漏洞；这不是未来依赖安全性的保证。
- 在网页实际创建“梯度下降收敛分析”项目，选中文档并使用 ecnu-max 完成三轮真实推导与修订。模型曾给出多余二阶可微假设、错误符号及边界推导；反馈后生成了修订证明，保存时另行注明 k=0 的数值等号。
- 生成期间刷新页面后仍是同一次请求，消息数未重复增长。
- 通过网页保存了“梯度下降线性收敛证明与数值核对”笔记；文件真实存在并能重新阅读。
- 当前开发会话单独实际运行 Python Fraction，计算二维二次函数 k=0…8 的点、函数值和上界。模型表的 k=0…3 精确分数与计算一致。该计算由本次开发会话运行，网页模型没有执行代码工具。
- 对后续步长研究的真实请求点击“停止”，状态变为 cancelled，保留已生成内容。
- 关闭并重启服务后，8 条消息、三次完整回答、一次取消状态及研究笔记仍可读取。
- 再次提供运行时密钥后，围绕两份已保存笔记继续请求，ecnu-max 返回了正确引用文件名的简短总结。最终保留 10 条消息、四次完整回答和一次取消记录。
- 未提供密钥的重启可阅读项目，模型配置状态为未配置，发送入口禁用；密钥没有恢复自磁盘。
- 实际 API 拒绝项目外文件和网页内部对话文件的直接读取（400），拒绝不匹配的 Origin（403）。
- 在桌面及 430 像素宽的浏览器窗口检查了文档阅读、公式和对话输入；窄屏使用材料/对话标签切换，检查后恢复了桌面窗口。

## 代码审阅与修复

独立代码审阅指出终态被旧快照覆盖、跨项目异步返回覆盖文件列表、旧发送操作清空新草稿、对话写入容量超过读取容量四个问题。分别增加终态优先合并、返回后核对项目、按项目分开输入并保留新输入，以及发送前预留回答空间。

实际操作还发现消息时间戳导致问答顺序颠倒，现按项目对话中的位置显示。服务占用监听端口成功后才恢复项目运行状态，避免端口已被占用的第二个实例改写正在使用的项目。SSE 建立连接后立即发送连接信息。
